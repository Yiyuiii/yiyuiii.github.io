# 内容体验集中优化：色差、计时统计与页面反馈

## 目标与边界

本轮落实用户已经批准的三组体验改进：

1. 色差挑战扩展为允许负分、可升降级、具有真实上下界和最高级无尽模式的积分制挑战；
2. 盲估十秒与反应时间在浏览器本机保存最多 100 次成绩，提供统计、趋势图、完整记录与清空操作；
3. 每个正式页面提供轻量反馈入口。公开问题进入 GitHub Issue Form，私密内容进入电子邮件；在仓库尚未启用 Discussions 时不渲染失效评论框。

所有功能保持双语、静态站点可部署、移动端可用。除萌娘百科问答本身外，本轮新增功能不产生运行时网络请求；计时历史只使用两个精确的 `localStorage` 键，不保存时间戳、路径、设备信息或用户标识。

正式 `D:\Codes\yiyuiii.github.io\master` 保持主分支镜像。本轮只在外部 worktree `D:\Codes\yiyuiii-content-experience-round5` 的 `feat/content-experience-round5` 分支实施，并避开正式 clone 中既有的 `_data/about.yml` 用户改动。

## 一、色差挑战

### 1.1 难度、积分与三题结算

- 共 25 级，内部为 `0..24`，界面显示 `1/25..25/25`；默认从第 `9/25` 级开始。
- 每题答对 `+1`，答错 `-1`；累计积分无上下界。
- 每三题形成一个结算组：答对 2 或 3 题升一级，答对 0 或 1 题降一级。
- 累计积分不直接决定等级。三题组负责及时调节当前难度，累计积分只描述整局净表现。
- 一题只能结算一次；未作答不能进入下一题。

### 1.2 两个硬端点

- 第 `1/25` 级固定使用 `rgb(0 0 0)` 与 `rgb(255 255 255)`，允许随机交换普通色和异色。这是 8-bit RGB 三通道码值距离的最大端点。
- 第 `25/25` 级使用中高亮中性色，只让红或蓝通道相差 1 个整数码值，其余通道相同。最终 CSS 始终写为整数 `rgb()`，不依赖浮点 CSS 色彩、透明度、滤镜或显示器抖动。
- 最高级之后不再虚构更小色差。最高级正分三题组进入并累计“单码极限无尽”；负分组退回一级。
- 最低级负分组三题继续停留在黑白端点并累计基础端重复次数；正分组恢复上升。不得据此进行色觉或医学判断。

### 1.3 中间 23 级

用几何曲线连接 `ΔE_OK = 1.0` 与 `0.0014`：

```js
target(level) = Math.pow(0.0014, level / 24)
```

相邻目标约乘 `0.7605`。中间级的验收区间由相邻目标的几何中点给出，避免题目落入相邻难度：

```js
lower(level) = Math.sqrt(target(level) * target(level + 1))
upper(level) = Math.sqrt(target(level - 1) * target(level))
```

- 第 `2..20/25` 级在 OKLab 中构造同色相、同色度、主要改变感知亮度的颜色对；转换为整数 sRGB 后重新计算实际 `ΔE_OK`，只有落入本级区间才接受。
- 第 `21..24/25` 级直接枚举整数 RGB 邻域并按量化后的实际 `ΔE_OK` 选择候选，避免浮点不同但最终像素相同。
- 所有随机选择继续只使用 `globalThis.yiyuiiiToyRandom`；每次搜索最多 32 轮。失败时使用经过测试复算的确定性模板，不得无限循环或生成同色题。

实施前的标准 OKLab 数值核验结果：黑白 `ΔE_OK = 0.999999993`；中性灰 `192..254` 上相邻红通道的单码差为 `0.001305..0.001376`，相邻蓝通道为 `0.001345..0.001418`，均位于最高级边界 `0.001605` 以下。对第 21–24 级，在约 2.2 万个 `32..223` 整数基色的步进抽样中，每一级都有超过十万或接近十万的局部整数候选，证明四个量化边缘区间具有足够覆盖率。最终实现仍要用自动测试复算全部回退模板，并对大量确定性随机样本验证。

### 1.4 色差界面

主统计始终显示：积分、当前难度及分区、本组三题、当前实际色差。可展开的次级统计显示：已答、正确/错误/正确率、当前/最佳连对、最高等级、单码极限通过组数、基础端重复组数。

只有结果摘要使用现有 `aria-live`。统计数字本身不反复播报。正确与错误除颜色外还保留文字和不同轮廓。

## 二、盲估十秒与反应时间

### 2.1 存储契约

只允许：

```text
yiyuiii.toy.ten-second.v1
yiyuiii.toy.reaction-time.v1
```

载荷结构：

```json
{
  "version": 1,
  "samples": [9750, 10180],
  "completedTotal": 2,
  "falseStarts": 0
}
```

- `performance.now()` 的差值在写入前统一使用 `Math.round()` 转为整数毫秒，只保留最近 100 项；累计完成数可超过 100。
- `falseStarts` 仅反应时间使用。
- 不保存时间戳、语言、路径、设备、输入方式或标识。
- 损坏、未知版本或存储异常时退回当前页面内存，不影响挑战本身；界面明确提示“仅本次打开有效”。
- 写入只发生在完成成绩、反应时间抢跑和确认清空时；开始、计时、取消、折叠和切到后台不写入。

### 2.2 统计与曲线

新增共享 `assets/js/toy-challenge-history.js`，提供数据清洗、中位数、百分位数、最近 5 次滚动中位数、图形模型、本机存储与 SVG 渲染；现有 `toy-challenges.js` 只负责在状态转换后记录一次。

- 盲估十秒图显示 `实际耗时 - 10 秒` 的带符号误差；零线固定居中。纵轴按有效记录绝对误差的第 90 百分位自适应，限制为 `±0.5..±10 秒`。
- 反应时间图从 `0 ms` 起，上界至少 `500 ms`、最多 `3000 ms`。低于 `100 ms` 的疑似预判和高于 `3000 ms` 的异常结果保留但不进入趋势统计。
- 两图最多 100 个点；满 5 个有效成绩后绘制最近 5 次滚动中位数。
- 使用原生 SVG `viewBox="0 0 512 288"`，动态生成双语 `<title>` 与 `<desc>`；图下保留文字统计和可展开完整表格，不依赖悬浮提示。
- 中位数与百分位数都对有效样本排序后使用线性插值；滚动中位数只使用最近 5 个有效样本。SVG 点不进入 Tab 顺序，逐项数值由可键盘展开的表格提供。本站语言切换会导航到对应语言 URL 并重新渲染组件，因此标题、描述和表格随页面语言重建，不维护跨语言 DOM 状态。
- 反应信号在 `requestAnimationFrame` 内实际呈现时记录起点；折叠、页面隐藏和离开页面同时取消 timeout 与待执行帧。
- 清空采用显式二次确认，只删除当前挑战的精确键，不调用 `localStorage.clear()`，也不影响另一项挑战、主题或环境光偏好。

## 三、页面反馈

> 后续状态（2026-08-04）：本节记录当时已落地的历史方案。Giscus 评论上线后，用户决定用评论取代站内重复的 Issue／邮件反馈提示；全站反馈组件及文案已经移除，仓库原生 Issue Form 仍保留但不再由站内链接。当前状态与验收边界以 `2026-08-03-page-comments.md` 和现有测试为准。

### 3.1 本轮落地

- 新增 `.github/ISSUE_TEMPLATE/page-feedback.yml`，使用一个中英并列的 Issue Form，必填页面 URL、反馈类型、问题描述和公开信息确认；建议、证据和截图为可选。
- 全站共享 `_includes/page-feedback.liquid`。普通页面在正文之后、页脚之前显示一次；双语 404 各自显示对应语言的一次。
- 公开反馈链接预填页面标题和绝对 URL；私密反馈使用预填主题与页面 URL 的 `mailto:`。
- 文案集中到 `_data/site_text.yml`。组件只有普通链接，不使用脚本、iframe、表单提交、Cookie、存储或首次加载网络请求；禁用 JavaScript 时仍完整可用。
- 重定向兼容页不显示反馈入口，避免用户对已经迁移的空壳页面反馈。

### 3.2 本轮不伪装实现

GitHub Discussions 当前未开启，Giscus 的 repo/category ID 仍为空。因此本轮不渲染评论框。后续由仓库管理员启用 Discussions、安装 Giscus App、创建评论分类并取得 ID 后，再实施“用户点击才加载”的评论增强。

分支 Ruleset、官方 Pages artifact 部署迁移、自定义域名验证也需要仓库外部设置，保持为后续独立事项。
