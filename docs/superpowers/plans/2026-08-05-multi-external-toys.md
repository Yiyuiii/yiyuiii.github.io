# 外部开放数据小游戏并行实施计划

## 用户原始要求

用户澄清“用子智能体把各个候选任务都做出来”是指此前提出的不同游戏候选，而不是把“百科条目猜猜”内部拆成多个开发子任务。所有候选继续服从更晚、优先级更高的边界：

- 不使用任何 API 密钥，不让读者提供密钥，也不增加代签后端；
- 不批量下载数据，不构建外部条目的本地大题池；
- 只在玩家明确开始本局后，请求外部提供的、与本局直接相关的公开接口或媒体；
- 不预取、自动续页、静默重试或把响应写入 Cookie、`localStorage`、`sessionStorage`、IndexedDB 或仓库；
- 每个游戏在开始前准确披露服务方、请求数量上限、IP／Origin 可见性、媒体流量和许可；
- 若接口、许可、可达性或题目质量不能闭合，保留证据并停止该候选，不用弱授权内容或固定小样本伪装完成。

本轮只在 `research/external-toy-datasets` 研究分支和 loopback 预览推进；未经用户试玩确认不得推送或发布，正式 `master` clone 必须保持干净。

## 候选线路与闸门

### Wikidata 时间线

目标是把四个人物、作品、发明或事件按年代排序。元数据为 CC0，但首轮原设想中的“构建数千条本地题池”已被用户否决。只有在一次玩家触发的窄范围查询内能稳定取得至少四个双语标签和明确日期，且不使用 `ORDER BY RAND()`、深分页、批量 ID 或第二次补请求时才实现。WDQS 在 2026 年负载与响应速度已明显恶化；若单局查询不稳定，记录为不成立。

第一道闸门是官方 WDQS／Action API 与结果链接在真实无登录浏览器中的跨域与网络可达性；Wikimedia 系服务在中国大陆存在与 Wikipedia 同源的阻断风险。至少 10 次小样本实测须有 9 次在 10 秒内成功、每批响应不超过 256 KiB，且成功批次全部能产生四个日期互异、同时具有中英文标签的候选，否则停止。若在其它网络可用但大陆不可达，开始前披露和失败文案必须明确说明，并且不做代理、镜像、探针或自动回退。

### MusicBrainz 乐坛时间线

只使用 MusicBrainz 核心 CC0 元数据，不使用封面或录音。优先用浏览器本地选择年代／年份和安全偏移量，再以一次受限 release-group 搜索取得四个日期不同、标题和艺人完整的项目；当前批次不足时提示玩家主动重试，不追加请求。必须遵守官方速率限制和可识别客户端要求在浏览器环境中的可行边界。

第一道闸门是官方接口的匿名浏览器 CORS 与客户端标识要求能否同时满足：不得伪造或尝试设置浏览器禁止修改的 `User-Agent`，也不得以代理代签。至少 10 次相互间隔并遵守官方限速的小样本实测须有 9 次在 10 秒内成功、响应不超过 256 KiB，并且至少 8 批可形成四个日期互异、题名与艺人完整的候选；否则停止。

### 芝加哥艺术博物馆“名画一瞥”

只接受 API 明确标为 `is_public_domain=true` 且具有 `image_id` 的作品。单局可有一次小批元数据 GET，并只加载本局实际展示的少量官方 IIIF 图片；不得先下载作品 ID 全表。题目可用同一答案图的 CSS 裁切作为“一瞥”，再在三至四张完整候选中选择，避免额外局部图片请求。候选必须过滤无图、非公共领域、明显敏感或题名直接写入画面的风险；揭晓显示原题名、作者、年代、馆藏链接和公共领域说明。

AIC 元数据查询已通过，但官方 IIIF 图片在 PowerShell 与真实 Chromium 中均触发 Cloudflare HTTP 403 人机验证，因此 AIC 路线已经停止。可以另行核验同样无需密钥且逐图开放许可闭环的博物馆官方 API；替代来源只有在一次元数据请求中至少 80% 的实测批次可形成四件候选、四张官方图片均在 10 秒内直返图像且总媒体量有明确上限时才进入实现。

### Bangumi／AniList 文字关系题

不使用动画封面。优先验证能否由一个匿名、CORS 可用、响应稳定的请求返回一部作品和足够的角色／关系；如果随机发现需要固定小白名单、连续猜 ID、多个补请求或批量缓存，则该来源不成立。Bangumi 条目／角色文本的 CC BY-SA 与中文体验优先于 AniList；AniList 只能在条款、降级限流、标题语言和成人过滤均可接受时作为来源。不得把两个都不稳定的来源拼成自动回退链。

第一步必须引用具体官方匿名端点并在真实浏览器验证 CORS；需要 OAuth／令牌即停止。至少 10 次小样本中 9 次应在 10 秒内返回不超过 256 KiB，至少 8 批应能形成有一个确定答案与三个合理干扰项的文字关系题。Bangumi 与 AniList 都必须验证接口级成人标记，并叠加客户端分类／关键词拒绝与人工抽样；任一环节不能可靠排除明显成人内容时不发布。

### Wikimedia Commons“听声猜猜”

不做主流歌曲竞猜。只考虑乐器、动物、环境声或公共领域／自由许可录音；每个被播放文件必须从本局 API 响应取得作者、来源页、许可和可用转码 URL。若一次小批元数据不能形成一个音频答案和四个同类文字候选，或中国大陆可达性与逐文件许可无法可靠处理，则停止该候选。不得使用本地音频池或未核验的直链。

第一道闸门同样是 Commons API、文件页和转码媒体在真实浏览器中的跨域及网络可达性；大陆不可达须像 Wikipedia 一样明确披露。至少 10 次小批实测须有 9 次在 10 秒内返回不超过 256 KiB，至少 8 批同时具备可播放转码、机器可判定的自由许可、作者／来源页和四个同类文字候选。另须用浏览器网络记录审计 `<audio preload="none" referrerpolicy="no-referrer">` 的元数据、Range 与实际播放请求；披露媒体可能产生多次分段请求，绝不能宣称整局只有一个网络请求。

### 明确排除

- Smithsonian 公共 API 需要密钥，本轮不实现；
- AniList／Bangumi 封面没有逐图再利用许可闭环，不实现动画封面猜题；
- MusicBrainz 不提供录音，Apple 预览限制为商店推广，不实现主流听歌猜曲；
- Europeana、Spotify、Jamendo、Freesound 等依赖凭据的路线不实现。

## Wikipedia 故障处理

> 2026-08-05 后续决策：用户审阅后决定从生产版“百科条目猜猜”移除 Wikipedia 来源，恢复为萌娘百科单一来源。以下段落保留为历史故障分析，不再描述当前产品界面。

MediaWiki 官方文档确认匿名跨域 Action API 使用 `origin=*`；当前实现与之匹配，固定桩测试也能正常出题。真实中文、英文 API 均在取得 HTTP 响应之前连接超时。Wikimedia Foundation 2019 年确认中国大陆屏蔽全部 Wikipedia 语言版本，因此产品应把这一故障解释为网络可达性限制，而不是笼统的题目失败：

- Wikipedia 来源开始前提示其在部分网络、尤其中国大陆通常不可达；
- 失败后中文页建议切回萌娘百科；
- 本站不增加代理、镜像、联网探针、自动回退或重试；
- 不把网络失败计入题目成题率。

同属 Wikimedia 系列的 Wikidata／WDQS 与 Wikimedia Commons 在中国大陆也有高度相关的可达性风险；相关候选须先验证、再开发。若仅在其它地区可用，产品披露、失败文案和无代理／无探针边界必须与 Wikipedia 保持一致。

## 并行分工与共享集成

三个子智能体分别负责时间线、AIC 视觉、ACG／Commons 路线；各自只写自包含 data/include/JS/测试/维护文档，不触碰共享索引和主样式。主智能体负责：

1. 辩证复核各子任务的官方证据、请求预算、许可和失败模式；
2. 只集成通过闸门的游戏到 `_data/toys.yml` 和 `_includes/toy-index.liquid`；
3. 统一外部数据挑战的排版、按钮、状态、隐私披露、外链安全与移动端体验；
4. 更新站点检查、搜索与项目记忆；
5. 进行独立外部审阅、production 构建、全量 Python／Node／Playwright 回归；
6. 留下可直接试玩的本地预览和未通过候选的最小证据，不推送正式站。

## 验收要求

- 普通测试和 CI 只使用固定桩，绝不访问外部服务；
- 初次载入、展开、切换设置和无 JavaScript 状态对所有候选服务零请求；
- 每个用户动作的最大元数据／媒体请求数与披露一致，失败不自动增加；
- 外部字符串只用 `textContent`，外部 URL 经过精确 HTTPS 主机白名单和无凭据／端口校验；
- 所有外部请求对齐既有安全模式：`credentials: "omit"`、`referrerPolicy: "no-referrer"`、`cache: "no-store"`，并只使用接口实际允许的简单请求；
- 响应有超时、声明／实际大小上限、活动令牌和 `AbortController`；
- 使用 `crypto.getRandomValues()` 与拒绝采样，不降级到 `Math.random`；
- 中文、英文文案完整；320／390／1280 px、键盘、明暗主题和长标题无横向溢出；
- 作答后提供足以履行许可的来源、作者／机构、许可和修改说明；
- 只有可达性和真实题目质量达到各自记录的门槛才允许发布。
- 每条推进或停止路线都记录实测次数、成功率、延迟、响应大小、成题率、双语／许可覆盖率和浏览器跨域结果；网络失败与题目质量失败分开统计。

## 执行结果

- GO：克利夫兰艺术博物馆“名画一瞥”。10/10 元数据成功、10/10 成题、9/10 四图按时完成；每局一次元数据 GET 与四个官方 JPEG，canvas 复用答案图，不依赖第五次媒体请求。
- GO：AniList MAIN 角色文字题。10/10 网络成功、10/10 成题；每局一次 GraphQL POST，通常伴随浏览器 CORS 预检，不请求封面或简介。
- NO-GO：Wikidata 6/10 网络与 6/10 成题；MusicBrainz 的应用级 `User-Agent` 无法由浏览器脚本保留；AIC 官方 IIIF 被 Cloudflare 403 阻断；Bangumi 三次样本中两次超时；Commons 缺少当前大陆可达性证据且原生音频仍发送 Referer。
- Wikipedia 程序与 CORS 参数经官方文档和固定桩验证无误；真实连接失败按大陆网络可达性处理，界面明确披露且不做代理、镜像、探针或自动重试。

## 试玩后的产品修订

- 可见名称改为“名画配对／Artwork match”；玩法从答案局部图配四幅完整图，改成馆方题名、作者、年代名片配四幅完整图。仍为一次元数据 GET 与四个 JPEG，不再使用 `canvas`。
- AniList 题面改为“这部动画的主角之一是谁？”，并在开始前说明“主角之一”对应 AniList `MAIN` 关系，可能不止一人，也不代表本站重新判断戏份。
- 百科条目猜猜回退到萌娘百科单一来源；百科、名画与 AniList 三项统一归入“数据库／Databases”。
- 最终生产树只接入两项 GO 组件；所有 NO-GO 原型均删除，只保留可复核证据与复评条件。
- 收敛复审确认上一轮三个中等问题全部关闭，未发现新的阻断或中等问题；Python 356 项、两个新组件纯逻辑 17 项、production 构建、站点契约、70 条旧 URL 与全量 Playwright 169 项全部通过。
- 最终真实浏览器验收中，CMA 在 8 秒内形成一局四图题，AniList 形成《ニセコイ（Nisekoi）》四角色题；两项在 320 px 均无横向溢出。预览保留在本地，不推送或发布。
