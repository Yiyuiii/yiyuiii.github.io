## 改写契约

1. 保留既有 `uid`、`translation_key`、显式 `permalink`、封面、原始发布日期和翻译方向，避免破坏文章身份与旧链接。
2. 重大改写新增 `2026-08-08` 修订项，说明由 GPT-5.6 Sol 重新调研并重写以及正文替换范围；第一条修订仍是原始发布日期。
3. 每组同时发布完整中英文正文；标题层级、代码、公式、链接、表格、显式锚点、证据块和修订日期保持对应，译文自然完整而非摘要。
4. 当前事实优先使用官方文档、标准、权威公共机构或原始论文。动态数字只在确有指导价值时出现，并同时给出复核日期和官方动态入口；能用决策方法替代固定数字时，优先写方法。
5. 正文明确区分持久机制、截至复核日的实现状态和作者建议。删除无法核验的经验断言、营销式预测、危险操作捷径与过时生态推荐。
6. `description` 只承诺正文确实提供的价值；不因重大修订改变首页标志日期。

## 事实与来源策略

### GitHub Pages

- 当前产品行为以 GitHub Pages 官方文档为准；Jekyll、Bundler、RubyGems 的职责与命令分别回到各自官方文档。
- 配额、支持版本和部署选项属于动态事实，不在正文中脱离日期永久写死。

### 强化学习

- 理论部分以标准教材和原始论文为主；环境接口与库行为以 Gymnasium、PyTorch 等官方文档为准。
- 算法选择、网络结构、奖励、回放和自博弈结论必须写清条件与失败模式，避免“总是”“越大越好”等无条件经验句。

### 云服务器

- DNS、HTTP、TLS、IP、端口和证书链优先使用 IETF/RFC 与权威标准；具体云产品文档只解释实现，不构成供应商推荐。
- 价格、促销、免费层和社区工具热度不进入持久主干；成本部分提供当前账单页面复核清单。

### 游泳

- 水中静力学必须区分压强与净浮力；人体行为还需考虑排水体积、肺容量、姿态与阻力，不能把单一无量纲或压强表达式称为力。
- 溺水预防、救生装备、开放水域、呼吸不适与求救建议采用权威公共卫生和救生机构来源。读者出现胸痛、明显呼吸困难、眩晕或意识异常时，教程不提供自我诊断或继续练习建议。
