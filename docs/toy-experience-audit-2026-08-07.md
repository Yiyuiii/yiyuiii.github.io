# 小玩意 M2 体验审计（2026-08-07）

## 范围与结论

本轮只审计现有十一项双语体验和 M1 首次展开加载，不新增游戏。自动审计最终为 0 问题：

- 24 种页面环境：中文／英文 × 320／390／1280 px × 明亮／暗色 × 普通／减少动效；
- 264 次逐项目键盘展开；
- 6 次十一项同时展开；
- 22 次逐语言、逐项目冷启动；
- 全部展开只请求固定本站脚本，三个外部数据问答在未点击“开始”时站外请求为 0；
- 没有横向溢出、缺少控件名称、低于 24 px 的非复选控件、主题错配、reduced-motion 动画残留或运行时错误。

人工查看了中文桌面全页、英文 390 px 暗色全页和十一项中文 390 px 展开截图。卡片层级、暗色对比、移动端换行、表单宽度、逻辑游戏棋盘与按钮均未发现可客观判定的缺陷。信息密度、分组顺序和是否允许多项同时展开属于产品偏好，保留给用户在单文件 HTML 中判断。

## 审计中发现并修复的问题

首轮 24 种环境都发现数字 Wordle 首次初始化会把焦点从用户刚刚键盘激活的 `summary` 自动移到猜测输入框。其它十项不会这样做，且这种焦点跳转会让键盘和读屏用户失去折叠标题位置。

`assets/js/toy-codebreaker.js` 现在只在用户明确重置题目或应用设置时移动焦点；脚本首次增强保留 `summary` 焦点。`tests/browser/toy-loading.spec.mjs` 增加了专门回归。修复后 264 个矩阵案例全部通过。

首轮还暴露了审计产物路径风险：若把含内嵌截图的 HTML 放在仓库内，Jekyll 会把它复制到 `_site`。现在：

- `scripts/audit_toy_experience.py` 强制 `--output` 指向仓库外目录；
- `_config.yml` 排除 `test-results/` 与 `playwright-report/`；
- `scripts/check_site.py` 若在生产树发现这两类目录会直接失败。

因此审阅稿不会进入正式站点。

## 共同机制抽取判断

只比较真实相同的生命周期后，已有共享边界足够：

- 盲估十秒与反应时间共享随机、历史和挑战控制器；
- 随机密码与随机数字共享随机和生成器控制器；
- 色差与三款逻辑游戏只共享安全随机接口；
- 外部问答的请求、许可、内容过滤和失败生命周期彼此不同。

没有证据支持再增加通用“小游戏框架”。M2 不做宽泛组件重构，也不把不同外部边界压进统一抽象。

## 复现与审阅

先完成 production 构建，再把产物写入仓库外目录：

```powershell
python scripts/validate.py
python scripts/audit_toy_experience.py --site _site --output <仓库外目录>
```

命令生成 `toy-experience-audit.json`、十一项 QA 截图和自包含的 `toy-m2-review.html`。HTML 已内嵌完成审阅所需的自动结果、冷启动表、页面全貌和十一项截图；外部 PNG 只供机器视觉 QA，不是用户完成审阅的依赖。

2026-08-07，用户确认当前分组、排序、信息密度与允许多项同时展开均无需调整，M2 正式验收完成。用户同时认为“接通电路”玩法传统、没有额外逻辑新意与站点价值，因此取消 M3 原型与后续 M4 集成；不得把其它传统候选自动递补为下一项。
