# 凑成 24

## 目标与范围

“凑成 24／Make 24”是“小玩意”页的本地算术组合游戏。每题给出四个 `1..10` 的整数，玩家必须把四个数各使用一次，只用 `+ − × ÷`，经过三次二元合并得到 24。游戏不接收任意表达式、不调用 `eval`，不联网、不持久化，也不把结果包装成数学能力评估。

## 精确数值模型

- 所有值都表示为约分后的整数分子与正整数分母；相等、除零和最终结果均以精确分数判断，不使用浮点容差。
- 每一步从当前数字中按顺序选择左操作数、运算符和右操作数；减法和除法保留选择顺序。
- 合并后两个操作数各消耗一次，新结果成为一个可继续选择的数字。剩一个值且恰为 `24/1` 时获胜；剩一个非 24 值时保留撤销、重置和换题。
- 除以零不会改变数字、步数或撤销历史；界面说明原因，并保留左操作数与运算符以便改选右操作数。

## 完整题池与设置

枚举 `1..10` 的全部非降序四元组，共 `C(13,4)=715` 个数字多重集合。求解器递归选择任意一对精确分数，尝试四则运算的所有必要顺序，并对规范化状态做记忆化；生成器只从经求解器证明可解的集合中均匀抽题，不靠无限重试。

当前精确统计：

| 题池 | 定义 | 不同四数组合 |
| --- | --- | ---: |
| 整数过程 | 至少存在一条所有中间结果均为正整数的解 | 556 |
| 需要分数 | 可解，但不存在全程正整数解 | 10 |
| 完整题池 | 至少存在一条精确解 | 566 |

默认使用“整数过程”。折叠设置只提供以上三种题池；选项改变先暂存，点击“应用并换题”才生效并清空当前步骤。题池大小按当前语言显示。换题用 `uintBelow(N-1)` 加索引偏移，在当前题池内均匀选择与当前题不同的数字多重集合，不做拒绝重试；随机接口或题池生成失败时隐藏整个交互区。

## 操作与状态

- 数字和四个运算符都用原生按钮；流程固定为“左数 → 运算符 → 右数”。`playing` 内部显式区分 `idle`、`leftSelected`、`operatorSelected`：数字可选择或替换左数，运算符可选择或替换；在 `operatorSelected` 选择另一个数字才完成合并，点击已选左数可取消部分选择。
- 数字按钮的可访问名称包含当前精确值；选择状态使用 `aria-pressed`、边框与文字共同表达。整数直接显示，非整数只显示约分后的 `分子/分母`，不显示浮点近似。步骤等式始终按用户选择的左右顺序记录，即使运算满足交换律也不重排。
- 每次有效合并播报完整等式与当前剩余值；静态步骤记录使用有序列表，不整体放入 `aria-live`。
- “撤销”先清除任何未完成选择，并回到上一个完成步骤、恢复两个操作数；没有完成步骤时只清除部分选择。“重置题目”恢复当前四个原始数字；“换一道题”在当前题池生成不同题目。三者都会清除部分选择。
- 状态为 `playing`、`won`、`stuck`、`unavailable`；获胜或走到非 24 的单值后禁止继续合并，但允许撤销、重置或换题。从 `won` 或 `stuck` 撤销一步后回到 `playing`。除零不改变完成步骤，并停留在 `operatorSelected` 等待另一个右数。

## 隐私、性能与验证

- 只使用 `globalThis.yiyuiiiToyRandom.uintBelow()`；不使用 `Math.random()`、网络、Cookie 或浏览器存储。
- 题池在用户首次展开该游戏时才由纯逻辑求解器生成并缓存，不阻塞初始页面加载。
- Python 测试必须用标准库 `fractions.Fraction` 实现一份不复用游戏代码的递归参考求解器，与 JavaScript 导出的全部题池逐项比较，证明 715 个四数组合分类闭合、566 道完整题均有精确解、10 道“需要分数”题没有全程正整数解；求解器不得因操作顺序、重复数字、负数、分数或除零漏解。
- 浏览器测试覆盖中英文、完整键盘通关、分数题、撤销、重置、换题、设置草稿、除零、随机接口失败、无脚本、无网络／存储以及 320 px 无横向溢出。
