# 翻灯

## 目标与范围

“翻灯／Lights Out”是“小玩意”页的本地网格规划游戏。按下一格会翻转它自己和正上、正下、正左、正右的有效邻格；目标是让所有灯熄灭。游戏不联网、不持久化，不把步数描述为智力评估。

## 数学模型与完整题池

- 棋盘和按键集合都用位掩码表示；翻转是异或，因此同一格按两次抵消，按键顺序不影响最终局面，每格在一份最短解中只需考虑按或不按。
- 3×3 枚举全部 `2^9=512` 个按键掩码，4×4 枚举全部 `2^16=65536` 个按键掩码。将每个按键掩码映射到产生的局面，并为同一局面保留按键数最少的解，由此得到完整可解状态及精确最少步数。
- 3×3 有 512 个可解状态，4×4 有 4096 个。生成器排除已完成局面与一步局面，再按以下精确区间选择：

| 棋盘 | 2–3 步 | 4–5 步 | 6 步以上 |
| --- | ---: | ---: | ---: |
| 3×3 | 120 | 252 | 130（6–9 步） |
| 4×4 | 680 | 2827 | 572（6–7 步） |

- 默认是 4×4、最少 4–5 步。设置只提供棋盘尺寸与三个最少步数区间，并显示当前尺寸下的完整范围与可选局面数；最高档在 3×3 明示为 6–9 步，在 4×4 明示为 6–7 步。“应用并换题”才使草稿生效。
- 题目用 `uintBelow(N-1)` 加索引偏移，从对应唯一局面池中均匀选择与当前题不同的局面；不以“随机翻若干次”作为难度定义，也不进行无界重试。随机接口或题池生成失败时隐藏整个交互区。

## 操作、状态与无障碍

- 棋盘使用 `role="grid"`、行使用 `role="row"`、可操作单元使用 `role="gridcell"`。每格可聚焦，点击、Enter 或空格执行翻转；方向键在同一行列内移动焦点，边界处停留。网格采用 roving `tabindex`，整个棋盘只占一个 Tab 入口。
- 每格同时显示形状和“亮／暗”文字，并通过边框与背景加强区别；可访问名称包含行、列和当前状态，不只依赖颜色。
- 每步只播报本次按下位置、当前亮灯数和步数，不反复朗读整张棋盘。
- “撤销”可逐步回退直至起始局面：每次把最后按下的一格再翻一次、步数减一；获胜后仍可撤销，并立即回到 `playing`。“重置题目”恢复本题起始局面并清空撤销栈；“换一道题”保留规则、生成不同局面并清空撤销栈。
- 完成后显示实际步数与精确最少步数；步数可以高于最优，不设置失败状态或强制上限。
- 状态为 `playing`、`won`、`unavailable`；随机接口不可用时隐藏整个交互区，只显示双语不可用说明。

## 隐私、性能与验证

- 只使用 `globalThis.yiyuiiiToyRandom.uintBelow()`；不使用 `Math.random()`、网络、Cookie 或浏览器存储。
- 完整池在用户首次展开游戏时生成并缓存；4×4 枚举必须有界且在普通设备上不造成可见长任务，必要时可把确定性池预生成到源码，但仍须用独立测试复核。
- Python 测试必须用不复用游戏位掩码枚举器的 BFS，从全灭局面逐层生成最短距离，与 JavaScript 导出的全部局面和最少步数逐项比较；同时确认池规模、步数分布、每题可解、记录的代表解确实清盘，以及不存在更短解。
- 浏览器测试覆盖中英文、点击和方向键、Enter／空格、撤销、重置、换题、设置草稿、完成播报、随机源失败、无脚本、冗余状态表达和 320 px 无横向溢出。
