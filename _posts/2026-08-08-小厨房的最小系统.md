## 先决定这篇文章只解决什么 {#start-from-one-question}

我最早想把这篇文章写成一张速查表：刀要不要买，锅需要几口，调料和保鲜盒准备多少。第一版后来加入库存、动线、清洁和食品安全，每一部分都合理，合在一起却失去了主次。读者仍然要先猜，别人的“必备”是否适合自己的饭、炉灶和水槽。

现有资料各自解决了这个问题的一部分。厨具清单告诉人们一套常见起点，收纳文章讨论分区和垂直空间，专业厨房用备料组织出餐，建筑指南约束工作区和通行，公共卫生指南给出食品安全底线。它们无法替一个家庭回答：哪些动作每周真的发生，哪一处限制最常让晚饭停下来，增加一个物品以后是否反而更难洗、更难放。

因此，这次重写只保留一个核心问题：

> 怎样用三顿常做的饭，生成一张属于自己的厨房采购清单？

答案不是先列物品，而是先做两轮测试。第一轮按平常方式把三顿饭从“决定吃什么”做到“厨房恢复可用”，记录反复出现的瓶颈；随后只调整顺序、摆放和份量，再做第二轮。仍然存在的瓶颈，才有资格变成购买候选。

这里的“最小”也有了可检查的含义：在现有空间、时间和体力下，用尽量少的物品，安全而稳定地完成常做的饭，并在饭后恢复到下一顿可以开始的状态。物品数量少只是可能的结果，不是目标本身。

## 选三顿能暴露不同问题的饭 {#choose-three-meals}

测试对象应是饭的类型，不必是固定菜谱。“米饭＋一份煎炒菜”和“面条＋一份烫菜”比某一道精确菜名更能代表重复动作。选下面三类，各写一顿自己确实会做的饭：

| 类型 | 怎样选择 | 主要暴露什么 |
|---|---|---|
| 最低精力的一顿 | 很累、很晚或时间很紧时仍愿意做的饭 | 食材是否容易决定和取出，最少工具能否完成，清洁是否足够轻 |
| 普通工作日的一顿 | 最近一个月最常重复的饭型 | 主要刀、锅、炉灶、台面和水槽怎样交接，日常库存是否可靠 |
| 空间压力最大的一顿 | 仍会真实重复、步骤和同时任务最多的一顿；不选只存在于想象中的宴客菜 | 容量争用、生熟处理、盛装、剩余食物和完整清洁收尾 |

三顿饭之外，再写下测试条件：几个人吃、几个人做、可用热源、实际能放下一块砧板的台面、水槽和沥水位置、可用总时间，以及做饭者的身高、活动能力或其它身体限制。条件不同，同一物品的价值会完全改变。每天吃米饭且只有一个炉灶的人，可能把电饭煲视为释放热源的工具；很少吃米饭的人只会多出一个需要存放和清洗的内胆。

不要为了测试特意把厨房收拾成理想状态。最值得观察的是普通工作日晚上的厨房：上一只杯子也许还在水槽里，常用调味料已经开封，人也没有精力完成复杂流程。

## 按平常方式跑第一轮 {#run-the-first-pass}

第一轮不买东西，也不预先大改收纳。开始点是决定吃什么，结束点是剩余食物妥善处理、接触面完成必要清洁、常用工具进入干燥或收纳位置。只记录发生了什么以及它造成的后果，不急着写解决方案。

> 选三顿常做的饭 → 按平常方式做完并清洁 → 记录瓶颈 → 先改顺序、位置或份量 → 复测；瓶颈消失就保留现有工具，瓶颈仍在才进入购买判断。

如果记录不会干扰火候、洗手或清洁，每遇到下面一种事件就记一行；否则饭后立即补记：

| 可观察事件 | 记录方式 | 例子 |
|---|---|---|
| 翻找 | 找什么，打开或搬动了哪些位置 | 为找锅盖翻了两个柜子，火上的水已经沸腾 |
| 腾挪 | 为腾出什么位置，临时搬走了什么 | 先把沥水架和小家电移走，砧板才能平放 |
| 被迫等待 | 哪个资源被谁占用，后续哪一步停下 | 唯一炉灶正在煮主食，锅里的菜无法开始 |
| 返工 | 哪个动作因顺序、污染或遗忘而重做 | 砧板需要中途重新清洗，或遗漏的食材要重新切配 |
| 临时替代或放弃 | 原计划做什么，最后怎样绕过 | 因没有安全的沥水方式而放弃这一步，或用了难以控制的替代动作 |
| 食材损失 | 什么食材被忘记、过量处理或没有后续用途 | 冰箱后排的蔬菜没有进入任何一顿饭，最终只能丢弃 |

“这口锅很烦”还不是可操作的记录。“两个锅柄挡住了唯一能放盘子的区域，盛装时必须先关火搬锅”才说明了对象、时点和后果。必要时记下开始盛装和完成清洁的时间；不必逐秒计时，目的是比较两轮，而不是制造精确但无用的数据。

疲惫时可以用最低负担版本：每顿饭结束后只写“最严重的一个瓶颈、它造成的后果、清洁完成时点”。三顿饭仍能看出重复问题；只有原因不清楚时，再用下面的完整记录。记录不能成为新的做饭瓶颈。

一顿饭结束后，用下面六项收口：

| 项目 | 这顿饭的记录 |
|---|---|
| 原计划和实际完成的饭 | 哪些步骤被删掉或替换 |
| 开始、盛装、清洁完成 | 三个时点即可 |
| 翻找、腾挪、等待、返工 | 各发生几次，最严重的一次是什么 |
| 临时替代或放弃 | 是否影响完成、质量或安全 |
| 剩余食物和食材损失 | 份量、用途、存放位置或丢弃原因 |
| 相对基线的条件变化 | 只记人数、热源、可用空间、时间或体力与测试前设定不同的地方 |

## 把记录还原成五类瓶颈 {#classify-the-bottleneck}

瓶颈是让后续动作无法继续，迫使人等待、腾挪、返工或采用不安全替代的受限资源。把记录归入五类，可以避免看到任何不便都去买东西。

| 瓶颈 | 判断问题 | 常见根因 | 第一种处理方向 |
|---|---|---|---|
| 动作能力缺口 | 现有工具能否安全、稳定地完成一个反复动作 | 缺少合适工具，现有工具损坏、尺寸不合或维护不足 | 先检查维护和安全替代；确实不能完成时考虑购买 |
| 容量争用 | 两个必要步骤是否同时需要同一热源、锅、台面或水槽 | 菜单并行度过高、顺序不当、份量超过容量，也可能确实少一个独立资源 | 先改顺序和份量，再判断增加容量是否有用 |
| 取放成本 | 高频物品是否每次都要翻找、跨区取用或先搬其它东西 | 按物品类别收纳，却没有按使用位置和频率摆放 | 为高频动作建立固定取用和归还位置 |
| 食材断点 | 做饭时是否缺关键输入，或看不见需要先吃的食材 | 采购脱离下一顿饭、开封物过多、冷藏位置不透明 | 先决定下一顿，再补真实缺口；建立优先食用位置 |
| 清洁收尾瓶颈 | 吃完后为何不能把厨房恢复到可用状态 | 一顿饭调用太多部件，污物干结，清洗、沥水或垃圾没有去处 | 减少器具，利用等待时间处理不影响火候的清洁，固定干燥路径 |

增加物品主要能解决动作能力缺口，有时也能解决容量争用。它往往会加重取放成本和清洁收尾。第二只锅无法解决只有一个炉灶的问题；一组分装盒也无法解决“没有决定下一顿吃什么”的问题。先找到瓶颈类别，才能知道采购是否命中原因。

## 先做零购买改动，再复测 {#change-without-buying-first}

我会按下面的顺序尝试改动，前一层无效才进入后一层：

1. **删掉低价值动作**：一份只为装饰而增加的配料、一只没有承担备料或盛装任务的碗，都可以先退出普通工作日流程。
2. **调整先后关系**：先做等待时间长的主食或炖煮，再处理短时加热；把容易干结的锅具安排在可立即处理的时点。
3. **调整摆放**：高频工具靠近使用点，但刀具、热源和清洁剂仍须满足安全边界；优先食用的食材放在打开冷藏空间时可见的位置。
4. **减少同时任务**：缩小份量、把两项同时加热改为先后完成，或选用可以共享同一锅水、同一盛装容器的步骤。
5. **维护现有工具**：修复松动部件，按制造商说明维护刀具和锅具，确认问题来自物品失效还是操作方法。
6. **再考虑增加物品**：只有前面五层仍留下重复瓶颈，购买才进入讨论。

备料不等于把所有食材提前切好、分进一排小碗。只准备下一个时间敏感阶段需要的东西，既能减少容器，也能避免易腐食物无必要地长时间留在室温。容器只有在前后用途之间不存在污染路径、且满足当地清洁要求时才可复用；凡接触过生食材的器具，在接触熟食或即食食物前应按当地指南完成清洗和必要的消毒。

改完后复测原来那顿饭。比较完成时间、翻找和腾挪次数、受限资源的等待、返工、清洁时间和食材损失。每轮只改一两个关键变量，结果才说明是哪项改动有效。一次变快可能来自当天份量较少；同一瓶颈在不同饭型消失，或同一顿饭复测仍然改善，证据才更强。

## 让重复瓶颈生成购买清单 {#turn-bottlenecks-into-a-shopping-list}

安全问题不需要等待重复：不稳的切配面、损坏的电器、无法避免的交叉污染路径或不能可靠判断熟制程度，都应立即停下来，按制造商说明和当地权威指南处理。下面的重复标准只用于给便利性采购排序，不是安全标准。

一个便利性问题满足下列任一条件，才进入购买判断：

- 同一瓶颈出现在三顿饭中的至少两顿；
- 零购买改动后，它在同一顿饭的复测中再次出现；
- 它出现频率不高，却会让一顿本来会做的饭无法完成。

“两顿”是为了压住冲动购买而设的个人排序规则，不是经过临床或人体工学验证的通用阈值。经常烘焙、需要无障碍工具、管理严重过敏或为多人做饭的家庭，应按自己的风险和任务频率改写这条规则。

每件候选再回答六个问题：

| 购买问题 | 必须写清的答案 |
|---|---|
| 它解决哪个瓶颈 | 指向具体一顿饭、一个动作和可观察后果，不能只写“更方便” |
| 现有替代为何不够 | 说明替代在时间、质量、体力或安全上的实际代价 |
| 使用频率是否成立 | 列出它会进入哪几顿常做的饭，或过去几次真实发生记录 |
| 不用时放在哪里 | 先量固定位置；不能依赖每次使用前搬走另一台设备 |
| 怎样完成清洗、干燥和维护 | 把拆装、耗材和存回去的时间一起计算 |
| 买后怎样复测 | 写下预期减少的等待、腾挪、返工或失败，买后用同一顿饭核对 |

六项都清楚，候选才进入“下一件购买”。只在一个想象菜谱中出现的工具进入等待清单；下一次真的做那顿饭时再观察。这样，采购清单保存的是证据和待解决问题，不是商品愿望。

## 保留一页真正有用的购物速查 {#shopping-reference}

原来那张“可能买什么”的速查表仍然有用，但阅读顺序应从左到右：先找到测试中反复失败的动作，再看可能的工具类别。

| 反复动作 | 购买判断 |
|---|---|
| 切、削、分割 | **先查：**主刀是否适合手和常见食材，砧板是否稳定，刀具是否得到正确维护。<br>**购买成立：**高频食材无法安全稳定处理，维护或合理替代仍无效。<br>**常见误买：**按刀具名称集齐整套，却没有解决最常做的切配动作。 |
| 煮、焯、炖、蒸 | **先查：**带盖锅的容量、炉灶兼容性和倒取方式。<br>**购买成立：**常做份量放不下，或安全的蒸煮、取出动作确实无法完成。<br>**常见误买：**为偶尔的一道菜买专用大锅；加锅却没有第二热源。 |
| 煎、炒、复热 | **先查：**现有锅的有效面积、重量、锅柄和锅铲配合。<br>**购买成立：**食材长期拥挤或同一顿饭确实需要另一种加热特性。<br>**常见误买：**同尺寸锅重复购买；把涂层或材质宣传当成做饭能力。 |
| 夹取、翻面、沥水、盛装 | **先查：**锅盖、漏勺、夹子、锅铲和现有容器能否安全兼任。<br>**购买成立：**热液体或易碎食物反复出现无法控制的转移动作。<br>**常见误买：**购买一组功能重叠的小工具，每件只服务一次动作。 |
| 完成高频主食 | **先查：**现有锅和热源能否按当前顺序稳定完成。<br>**购买成立：**主食在多顿饭里持续占用唯一热源，改顺序后仍阻塞其它菜。<br>**常见误买：**因“别人都用”购买电器，却没有固定位置或足够频率。 |
| 搅拌、粉碎、打发 | **先查：**手动方法的时间、份量和成品要求。<br>**购买成立：**该动作高频且手动代价明确，电器能替代多个真实步骤。<br>**常见误买：**用“一机多能”推测用途，却没有三顿饭中的实际任务。 |
| 冷却、冷藏、带走 | **先查：**现有容器的容量、密封、堆放和清洗情况。<br>**购买成立：**剩余食物反复没有合适容器，且候选符合当地安全储存要求。<br>**常见误买：**成套购买尺寸相近的盒子，最后缺的仍是合适份量和日期记录。 |
| 判断加热与储存状态 | **先查：**现有设备显示、制造商说明和权威指南要求。<br>**购买成立：**常做食物需要温度证据，现有方法不能可靠判断。<br>**常见误买：**用颜色、经验时间或联网设备替代正确测量与官方要求。 |
| 清洗、沥水、干燥 | **先查：**水槽、刷洗工具、抹布、沥水和垃圾路径。<br>**购买成立：**清洁总在同一位置受阻，调整顺序和器具数量后仍无法干燥或归位。<br>**常见误买：**为了“收纳整齐”增加难洗的架子和分装件。 |

这张表故意不给品牌、套装数量和固定尺寸。锅的直径、刀的类型、电器容量与容器数量只有联系人数、炉灶、手部能力、常做份量和固定位置才有意义。购买当天应再查制造商规格、材料限制、保修和本地安全要求；这些动态信息不适合写成常青推荐。

## 看一个完整例子 {#worked-example}

假设一个人使用单炉灶、小台面和单水槽。最低精力饭是冷冻水饺加烫青菜，普通工作日饭是米饭加番茄炒蛋，空间压力最大的一顿是米饭加一份煎炒菜和一份汤。第一轮出现四条记录：

1. 沥水架占着唯一能完整放下砧板的位置，三顿饭都要先搬走；
2. 后两顿饭的主食占用唯一炉灶，煎炒步骤被迫等待；
3. 冷藏后排的青菜没有进入视线，同类蔬菜又被重复购买；
4. 为了“提前备好”，每顿多用了三四只小碗，盛装后仍要集中清洗。

这四条记录不会直接生成四件商品。先做零购买改动：为沥水架确定一个不侵占切配面的干燥位置；把需要先吃的食材集中到安全且打开冷藏空间就能看到的位置；只提前准备下一阶段需要的食材，取消不承担必要任务的分装碗，接触过生食材的容器不直接拿来盛熟食或即食食物；主食先做，利用焖放或保温时段完成煎炒。

第二轮中，腾挪、重复购买和额外清洗消失，说明根因分别是摆放、可见性和过度备料。主食仍在后两顿饭中造成明显等待，于是才比较两个方案：继续接受先后加热，或把一台尺寸合适的主食电器列为购买候选。第二口锅不会增加热源，因此被排除。主食电器也只有在使用频率、固定位置、额定功率、清洗路径和买后复测都成立时才保留。

这个例子没有给出“必须买电饭煲”的答案。它给出了更有用的东西：为什么买、什么情况下不买，以及买后用哪顿饭判断自己是否买对。

## 同一张清单也处理食材 {#use-the-same-method-for-food}

厨房采购同时包括器具和食材。食材不需要先建立复杂分类，只要在决定下一顿饭时回答三个问题：

1. 哪些食材必须按日期、开封状态或成熟度优先处理？
2. 它们能进入三顿常做的饭中的哪一顿？
3. 为完成这顿饭，真正缺少的输入是什么？

优先处理的食材放在符合安全储存要求、又能在决定吃什么时看见的位置。耐储、冷冻或可以快速组成最低精力饭的食材承担备用；高频主食、油和调味料按实际消耗补货。采购前先从现有食材选定下一顿，再只买缺口。新调味料若没有两次明确用途，先留在等待清单。

剩余食物也属于下一顿饭的输入。盛装时就决定哪些立即吃、哪些在安全时限内冷却和冷藏，并写清用途；“以后可能吃”不是计划。具体温度、时间、容器和翻热次数继续按当地公共卫生指南执行，不能由这套个人测试替代。

## 食品安全和身体条件是硬约束 {#keep-safety-as-a-hard-constraint}

压力测试可以给便利性排序，不能拿安全换效率。生食材与熟食或即食食物的分开处理、手和接触面的清洁、需要熟制食物的充分加热、易腐食物与剩余食物的温度和时限，应服从当地权威指南。颜色或砧板正反面只帮助识别用途，不能替代清洗和必要的消毒。

同样，疼痛、握力、身高、视力、活动范围、儿童参与、严重过敏和高风险家庭成员都会改变“最小”的定义。一个低频工具如果提供必要的无障碍能力或隔离路径，仍可能是基础设施。出现反复疼痛、烫伤风险、电器故障、通风问题或无法建立安全流程时，应停止测试，咨询合适的专业人员，而不是继续用购买评分权衡。

本文不会给冷藏天数或所有食物的中心温度，因为这些数值依食材、处理方式、人群和地区指南而变。文章末尾列出香港食物安全中心的配制、烹煮、贮存与剩余食物入口；其它地区应换成本地公共卫生部门的对应资料。

## 用第二轮结果判断是否结束 {#acceptance-criteria}

小厨房不需要达到零等待、零移动或零剩余。它需要把已知限制变成可接受、可重复的安排。第二轮后，用下面五项判断当前系统是否已经够用：

- [ ] 三顿常做的饭都能在预先设定的时间和体力范围内完成，全程不依赖不安全的临时替代；
- [ ] 高频物品有固定取放位置，热源、锅、台面和水槽也有明确且可接受的使用顺序；
- [ ] 每件高频工具都有“取出—使用—清洗—干燥—存回”的完整路径，疲惫时仍能完成清洁收尾；
- [ ] 优先处理的食材可见，剩余食物已有明确用途和安全处理方式；
- [ ] 采购清单上的每一件物品都写明瓶颈、固定位置和买后复测方法。

满足这些条件后，先停止优化。保留一两个知道原因、愿意接受的小麻烦，通常比继续购买更省空间。以后人数、住处、身体条件或常做的饭改变，再重新选择三顿饭跑一轮测试。

我现在仍然需要一张厨房购物速查表，只是它不再从商品开始。它从一次真实的晚饭开始，让反复发生的事实决定下一件东西。这样的清单会短很多，也更接近一个小厨房真正需要的最小系统。
